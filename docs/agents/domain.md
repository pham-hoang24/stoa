# Domain docs

This repository uses a single-context layout:

- GLOSSARY.md at the repository root.
- Architecture decisions under docs/adr/.

Before exploring a domain, read the glossary and relevant ADRs.
If they do not exist, proceed silently; create them lazily when
domain-modeling resolves terminology or architectural decisions.

Use glossary terms consistently in specifications, code, and tests.
Surface conflicts with existing ADRs explicitly.
Keep definitions in the glossary and implementation decisions in ADRs.
